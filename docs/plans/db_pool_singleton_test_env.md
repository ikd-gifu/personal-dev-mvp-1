**ステータス: 未着手。テスト導入時期がまだ未定のため、2026-08-27時点では見送りと合意済み。テスト導入時にこのファイルを起点に検討する。**

## 背景

[database/index.ts](../../frontend/src/external/client/database/index.ts)では、`next dev`のHMRによるモジュール再評価で`pg.Pool`が繰り返し生成され接続がリークするのを防ぐため、`NODE_ENV === "development"`の時だけ`pool`を`globalThis`にキャッシュしている(Cloud Run本番はモジュールが起動時に一度しか評価されないため対象外)。

## 検討事項

テストランナー(Vitest/Jestなど)実行時は`NODE_ENV`が`"test"`になるのが一般的。もしテストランナーがウォッチモードでこのモジュールを繰り返し再評価するような使い方をする場合、`development`と同様の接続リークが起き得る。逆に、テストごとに独立した`Pool`を期待する書き方をしている場合は、`test`時にキャッシュを効かせるとテスト間で意図せず`Pool`が共有され、問題になる可能性もある。

いずれにせよ、実際にどのテストランナー・どのような実行方式(ウォッチモードの有無、DBに接続する統合テストの有無)を採用するかが決まっていない現時点では判断材料が不足しているため、テスト導入時に実際の実行方式を踏まえて`NODE_ENV === "test"`をキャッシュ対象に含めるかどうかを検討する。
